# P2B-05 Evidence - Docker Compose logs and health

Status date: 2026-08-18

P2B-05 is verified. Docker Compose logs now enter the existing bounded log pipeline, and Compose health participates in the existing readiness and durable health-result contracts.

## Delivered behavior

- A fixed no-shell `docker compose ... logs --no-color --timestamps --follow <declared-services...>` child writes to two canonical runtime spools under the control data root.
- Existing spool files must be regular files; symlink/junction or parent-path escape is rejected before Docker starts. Newly created files are canonicalized again before use.
- Closing the owned follow session cancels the Docker child, flushes both files, and joins command/file errors without exposing command output.
- The existing Log Manager tails those spools and retains its UTF-8 handling, line bounds, Secret redaction, sequence ordering, NDJSON segment rotation, SQLite segment index, and SSE publisher behavior.
- Compose health requires every managed container to be both `running` and `healthy`; missing or unhealthy healthchecks return `CONTAINER_UNHEALTHY` with a bounded safe summary.
- Project identity is strictly base64url/JSON encoded with unknown-field rejection and its existing definition digest. The generic Health Engine accepts `kind=compose`, applies the same thresholds/timeouts/cancellation, and records every completed check.
- Migration `000013_compose_health_results.sql` extends the closed `health_results.kind` constraint with `compose`, preserving prior row IDs and process/TCP/HTTP data.
- `COMPOSE_LOG_FOLLOW_FAILED` and `CONTAINER_UNHEALTHY` are registered in the API/OpenAPI error contract.

## Automated verification

Tests cover fixed log arguments, stdout/stderr spool writes, path escape denial, owned cancellation, healthy/unhealthy mapping, strict identity token round-trip/tampering, Health Engine recording, Compose SQLite results, empty database migration, every historical production upgrade, explicit version 12 to 13 row preservation, repeated startup, and checksum behavior.
