# P1B-07 Persisted Events and SSE Evidence

- Migration `000005_events.sql` adds the durable `events` source of truth with monotonic integer IDs, bounded object JSON, workspace/system scope, optional runtime/Operation scope, and catch-up indexes. Its SHA-256 is `30087840B1F73AAAEC5C56C2031F201D40BC72F7AFB9451D5B46697FDFCAA6C6`; after application it is immutable.
- New Operation creation, Operation state changes, cancellation changes, and OperationStep changes write a typed past-tense domain event on the same SQLite connection and in the same immediate transaction as the state mutation.
- A rejecting SQLite event trigger proves that event insertion failure rolls the Operation state update back. Idempotent Operation replay and idempotency-key conflicts do not create duplicate events.
- The in-memory Broker only receives committed event IDs after commit. Publication is non-blocking; a full subscriber buffer closes only that subscription while database writes and other subscribers continue.
- `GET /api/v1/events` implements SSE with integer `id`, typed `event`, and one-line JSON `data`. It sets `text/event-stream`, disables proxy buffering, sends 15-second default heartbeats, and uses no HTTP server write deadline.
- `Last-Event-ID` takes precedence over the query `cursor`. Invalid/future cursors return `400 REQUEST_VALIDATION_FAILED`; cursors older than retained history return `409 EVENT_CURSOR_EXPIRED` before streaming headers are committed.
- The handler subscribes before reading the database high-water mark, replays `(cursor, highWater]` in bounded 200-event pages, and then treats Broker IDs only as prompts to read committed rows. Tests insert an event during the watermark read and prove it is not lost.
- A connection without a cursor starts from the current database high-water mark, preserving the REST-snapshot-plus-SSE-increment model instead of replaying all historical state.
- OpenAPI defines the route, resumable inputs, error mapping, and `DomainEvent` envelope. DTOs contain no commands, environments, tokens, platform identities, or raw logs.
