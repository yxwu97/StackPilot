# P0-06 Verification Evidence

## Scope

P0-06 establishes the non-CGO SQLite connection contract, data-directory initialization, transactional checksum migration runner, initial Phase 1A catalog schema, and real-database repository test base.

Status: `verification`

The implementation and automated checks are complete in the current uncommitted worktree. Remote GitHub verification remains unavailable because Git cannot acquire credentials.

## Contract decisions

- SQLite uses `modernc.org/sqlite`; no CGO dependency is introduced.
- Every pooled connection receives WAL, foreign keys, 5000 ms busy timeout, and NORMAL synchronous mode through the DSN. The pool is bounded to four open and idle connections.
- `server --data-dir` accepts an override converted to an absolute path. The storage layer creates and canonicalizes the directory and opens `stackpilot.db` within it.
- Migration filenames carry positive six-digit monotonically increasing versions. Exact file bytes are protected by lowercase SHA-256 checksums.
- Applied history must be an exact prefix of embedded migrations. Newer, missing, reordered, renamed, or checksum-mismatched history refuses startup.
- Each migration SQL body and its `schema_migrations` row commit in the same transaction; failures roll back both.
- Version 1 creates only `systems`, `manifest_snapshots`, `workspaces`, and `services`. Runtime/Operation tables and all Phase 2 tables remain absent until their owning work packages.
- Readiness remains unavailable after database initialization because the detailed contract also requires initial reconciliation, which is not implemented in P0-06.

## Known limitations

- P1A repositories and transaction-level domain operations are not part of this connection/migration baseline.
- Runtime, Operation, event, port, health, log, and auth tables will be added by forward-only migrations with their owning behavior.
- Windows ACL hardening for service-mode data directories belongs to the later authentication/installation security work; P0-06 uses user-mode directory creation and canonicalization.
- GitHub `origin/main` cannot be verified until GitHub credentials or an authenticated CLI are available.
