# P2B-02 Evidence - Docker Compose preflight

Status date: 2026-08-20 (Docker Desktop auto-start addendum)

P2B-02 is verified. The Windows Compose preflight independently validates the installed Docker toolchain, daemon access, Compose configuration, and declared service references before the lifecycle path can create or start containers.

## Delivered behavior

- Docker is resolved as a canonical regular `docker.exe`; no shell, manifest command, or PATH value from an API request participates.
- Fixed, bounded commands verify Docker CLI `>= 24.0.0`, Compose v2 `>= 2.20.0`, Docker daemon access/server version, and structured Compose config.
- Config parsing uses `docker compose --file <canonical-file> config --format json --no-interpolate` from the Compose file directory.
- The config file boundary is rechecked at preflight, and every declared `compose.services` entry must exist in structured config output.
- Command stdout/stderr are bounded in memory. Full config output and stderr are not persisted, logged, returned, or included in errors because they can contain local environment details.
- Stable error classes and OpenAPI registry entries distinguish missing Docker/Compose, unsupported versions, daemon unavailability, invalid config, and timeout.
- When the CLI and Compose plugin are installed but the daemon is unavailable, Windows preflight starts Docker Desktop from one of two fixed canonical installation paths, as the current user and without arguments. Concurrent preflights serialize this attempt and poll readiness within the shared two-minute deadline.
- Non-Windows builds retain a platform gate; non-Compose process operation remains independent of Docker availability.

## Automated verification

The controlled command-runner suite verifies exact argument arrays and working directory, minimum versions, missing Compose plugin, daemon denial, fixed trusted Docker Desktop install roots, successful and failed Docker Desktop startup, single-start behavior under concurrent preflights, invalid/missing services, workspace path escape, deadline cancellation, and safe error text. Existing API contract tests verify that all error codes match the OpenAPI machine registry.

The 2026-08-20 auto-start Gate began with the Docker CLI installed and the Docker Desktop daemon stopped. `TestInstalledComposePreflight` started Docker Desktop through the production trusted-path launcher, observed daemon readiness, and parsed the isolated temporary Compose file in 11.94 seconds. The test did not create a container or mutate an AIWS Compose project.

## Real Windows Gate

Commands:

```powershell
docker version --format '{{json .}}'
$env:STACKPILOT_COMPOSE_INTEGRATION='1'
go test ./internal/driver/compose -run '^TestInstalledComposePreflight$' -count=1 -v
```

Result:

```json
{
  "dockerClientVersion": "29.5.3",
  "dockerServerVersion": "29.5.3",

```

The original 2026-08-18 Gate used an already running Docker Desktop daemon. The 2026-08-20 addendum above repeated the same isolated config validation from a stopped daemon and proved automatic Docker Desktop startup. Neither Gate pulled an image, created a container, or mutated a Compose project.
