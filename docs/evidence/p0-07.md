# P0-07 Verification Evidence

## Scope

P0-07 establishes GitHub Actions quality gates for Windows tests/static checks, Web type-check/build, non-CGO Linux/macOS cross-compilation, and a versioned Windows binary artifact with SHA-256 checksum.

Status: `verification`

The workflow and local equivalent checks are complete in the current uncommitted worktree. The workflow cannot run on GitHub until the changes are committed and pushed, and remote GitHub access remains unavailable because Git cannot acquire credentials.

## Workflow contract

- Triggered for pushes to `main`, pull requests, and manual dispatch.
- Repository permission is limited to `contents: read`.
- Concurrent runs for the same workflow/ref cancel older in-progress runs.
- Windows quality job runs `npm ci`, Go formatting enforcement, Web strict type-check/build, all Go tests, and Go vet.
- Ubuntu matrix cross-compiles Linux and macOS amd64 commands with `CGO_ENABLED=0`.
- Windows artifact job waits for quality and cross-compile, injects CI version/commit/build time, builds the embedded Web binary, emits SHA-256, and uploads both files for 14 days.
- No release, commit, tag, push, deployment, or write permission is included.

## Known limitations

- GitHub-hosted execution and artifact download cannot be verified before the workflow is committed and pushed to `origin/main`.
- Action references use maintained major-version tags; organization-wide immutable action SHA pinning can be added when repository policy supplies the approved digests.
- GoReleaser release matrices, signing, release checksums, and installers belong to later release work packages and are not partially implemented here.
