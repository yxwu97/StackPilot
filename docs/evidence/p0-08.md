# P0-08 Verification Evidence

## Scope

P0-08 validates the Windows Supervisor, Job Object, Named Pipe, reconnection, and identity-file assumptions that block the Phase 1B Process Driver. ADR-0001 records the resulting decision.

Status: `verification`

The isolated Spike, repeatable verification script, ADR, and real Windows checks are complete in the current uncommitted worktree. The production Supervisor remains P1B-03.

## Verified scenarios

| Required scenario | Evidence |
| --- | --- |
| Server exits while Supervisor/service continue | A short-lived launcher started the detached Supervisor and exited; identity validation and Pipe connections occurred afterward while Supervisor/service remained active |
| New Server verifies and reconnects | The verifier matched Supervisor and worker PID, creation time, executable path, account SID, and protocol version, then completed two separate Pipe connections |
| Supervisor failure kills complete tree | Forced Supervisor termination closed the last kill-on-close Job handle; root and every captured descendant exited in all profiles |
| Maven/Java and npm/Node behavior | Maven profile captured a Java child; npm profile required and captured at least two Node descendants; both complete trees terminated |
| Pipe ACL allows only account and SYSTEM | Live Pipe DACL enumeration contained exactly the current runtime account SID and Local System (`S-1-5-18`), with allow-only ACEs |
| Identity covers pre-database crash window | `identity.json` used create/flush/close/atomic rename and its write timestamp preceded the primary-thread resume record |

The generic profile additionally required two generations of Spike worker descendants, so kill-on-close was not accepted based only on terminating a direct child.

## Decision and boundaries

- [ADR-0001](../adr/0001-windows-supervisor-job-object.md) is accepted; D-01 is closed.
- The detached Supervisor remains the owner of per-service kill-on-close Job handles.
- P0-08 is a validation artifact, not the P1B-03 production protocol or a public StackPilot command.
- Production P1B work must still add protocol fuzzing, a genuinely different-account ACL denial test, graceful stop, spool handling, and SQLite recovery integration.
