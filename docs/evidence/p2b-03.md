# P2B-03 Evidence - Docker Compose runtime override

Status date: 2026-08-18

P2B-03 is verified. StackPilot can generate one immutable Docker Compose override per Operation without enabling the Compose lifecycle path.

## Delivered behavior

- `compose.ports` maps declared logical ports to fixed managed Compose services and container target ports; mappings participate in the manifest's unique port-owner validation.
- `compose.environment` accepts only declared Compose services and the existing non-Secret template subset.
- Generated ports use Compose long syntax with fixed `127.0.0.1`, TCP, host mode, planned published port, and declared target port.
- Generated services contain only approved ports, non-sensitive environment values, and the four StackPilot identity labels.
- Runtime output is written below `DATA_DIR/runtime/operations/<operationId>/compose.override.yml`; every created path component is canonicalized before descending, so a symlink or Windows junction cannot redirect writes outside the data root.
- The file is written through a same-directory temporary file, flushed, atomically published, strictly reparsed with known fields, shape-checked, and compared with the intended document.
- Repeating an Operation with identical inputs is idempotent. Different content for the same Operation returns `COMPOSE_OVERRIDE_CONFLICT`; invalid input or output returns `COMPOSE_OVERRIDE_INVALID`.
- The original Compose file is never modified, and override generation has no path for command, volume, privileged mode, Secret, shell, or raw HTTP input injection.

## Automated verification

The unit and contract suites cover deterministic approved output, invalid services and ports, invalid environment names and values, unexpanded templates, NUL/newline rejection, unknown fields, multiple YAML documents, idempotent retries, conflicting retries, symlink and Windows junction escapes, Schema/semantic mappings, and OpenAPI error registry alignment.

## Real Windows Gate

Command:

```powershell
$env:STACKPILOT_COMPOSE_OVERRIDE_INTEGRATION='1'
go test ./internal/driver/compose -run '^TestInstalledComposeOverrideConfig$' -count=1 -v
```

Result:

```text
=== RUN   TestInstalledComposeOverrideConfig
--- PASS: TestInstalledComposeOverrideConfig (0.49s)
PASS
```

The Gate generated an override, merged it with an isolated Compose fixture using the installed Docker Compose implementation, and parsed the resulting JSON. It verified loopback published/target ports, environment values, and labels, and rejected the presence of command, volume, or privileged fields. It invoked only `docker compose ... config`; no image was pulled and no container or Compose project was started.
