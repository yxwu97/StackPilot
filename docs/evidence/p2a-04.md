# P2A-04 Evidence - Process oneshot

Status date: 2026-08-18

P2A-04 is verified. `mode: oneshot` is accepted without readiness, while `dependsOn: completed` remains gated until P2A-05. The server advertises `phase2.oneshot`.

## Delivered behavior

- Process Driver accepts `daemon` and `oneshot` while retaining identical path, runner, environment, identity, Job Object, and output controls.
- Start Operations use `wait-complete:<serviceId>` for oneshot and enforce the validated system `startTimeout`.
- Main-process exit code `0` becomes `completed`; a nonzero code becomes `failed` with `PROCESS_EXITED`; timeout force-terminates the complete Job and records exit code `137` with `HEALTH_READINESS_TIMEOUT`.
- Natural exit first drains Supervisor output pipes into the protected spool, reaps the Supervisor service entry, closes log capture, and then commits the terminal service state and exit code.
- Completed and naturally failed instances clear active PID/process identity. Stopping a Completed instance never sends a second process signal.
- Migration 12 snapshots `process_mode` on every ServiceInstance so reconciliation can distinguish exited daemon and oneshot processes without consulting a changed manifest.
- Reconciliation reaps exited oneshot Jobs and restores exit `0` as Completed or nonzero exit as Failed.
- A `ready` dependency on oneshot is rejected. `completed` remains `FEATURE_NOT_ENABLED` until P2A-05.

## Automated verification

Focused unit and integration coverage verifies manifest capability boundaries, state transitions, timeout/cancellation, exit-code persistence, identity clearing, migration v11 to v12, recovery, and Completed stop behavior.

The Windows Process Driver test starts a real Supervisor and an immediate-exit process, observes exit code `23`, reaps the Job, and verifies stdout flush. Windows Supervisor, ACL, DPAPI, SQLite, and Process Driver suites pass outside the restricted sandbox.
