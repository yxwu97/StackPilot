# P0-05 Verification Evidence

## Scope

P0-05 establishes the Draft 2020-12 JSON Schema for `stackpilot.io/v1alpha1` System manifests, valid YAML examples, and executable structural validation tests.

Status: `verification`

The implementation and automated checks are complete in the current uncommitted worktree. Remote GitHub verification remains unavailable because Git cannot acquire credentials.

## Contract decisions

- `schemas/system-v1alpha1.schema.json` is the machine-readable manifest structure contract.
- The root requires the exact `apiVersion`, exact `kind`, metadata, and a spec containing at least one service; unknown fields are rejected at every defined object boundary.
- System/service/port/dependency names use the domain identifier pattern `^[a-z][a-z0-9-]{0,62}$`.
- Port numbers are restricted to 1024-65535, protocol to `tcp`, and exposure to `loopback`.
- A daemon service, including one relying on the default mode, requires readiness. An explicit oneshot service structurally forbids readiness.
- Reserved later-phase values (`compose`, `oneshot`, `completed`, `python-venv`, liveness, and automatic restart) are recognized with `x-stackpilot-capability` annotations. Schema recognition does not enable them; registration must return `FEATURE_NOT_ENABLED` until the corresponding capability is delivered.
- Schema validation does not replace P1A semantic and security validation. Range ordering/candidate count, DAG references/cycles, path boundaries, template references, duration relationships, and capability gates remain explicit semantic checks.

## Invalid cases covered

- Wrong API version or kind.
- Unknown root or service fields.
- Invalid system or service identifiers.
- Empty service map.
- Missing daemon readiness and forbidden oneshot readiness.
- Invalid dependency condition and environment variable name.
- Privileged preferred port.

## Known limitations

- P1A-02 implements bounded YAML loading, duplicate-key rejection, unknown-field diagnostics, and multi-document rejection.
- P1A-03 implements defaults, semantic validation, template validation, path trust boundaries, DAG checks, duration bounds, port-range semantics, and capability gates.
- The initial P0-05 baseline deferred TCP target fields. P1A-03 subsequently froze and synchronized the explicit loopback `host` plus logical-template/fixed `port` shape before semantic registration was enabled.
- GitHub `origin/main` cannot be verified until GitHub credentials or an authenticated CLI are available.
