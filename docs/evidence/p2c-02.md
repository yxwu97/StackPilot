# P2C-02 Evidence - AIWS Infrastructure

Status date: 2026-08-18

P2C-02 is verified against the real `E:\AIWorkflowStudio` workspace and installed Docker Desktop.

## Implementation

- AIWS now has `deploy/stackpilot-compose.yml`, a dedicated six-service definition without host port declarations. The immutable StackPilot override is therefore the only source of published ports.
- PostgreSQL, Keycloak, MinIO, ClamAV, Qdrant, and OpenTelemetry Collector use pinned images, named data volumes where applicable, and explicit healthchecks.
- Keycloak uses a named `/opt/keycloak/data` volume so ordinary stop and supported image upgrade preserve identity state.
- ADR-0005 permits fixed container commands in the registered base Compose definition while retaining the runtime-override, entrypoint, build, privilege, root-mount, and unmanaged-dependency boundaries.
- The real AIWS manifest maps ten logical infrastructure ports to fixed container targets. Every published port is loopback-only and receives preferred/fallback/sticky planning.

## Verification

The real manifest Schema/semantic/path Gate and production Compose Preflight both passed. The Preflight observed Docker client/server 29.5.3 and Compose 5.1.4 with exactly the six declared services.

The lifecycle Gate generated an isolated real override with ten available dynamic loopback ports, started all six containers, waited for every container to be running and healthy, performed ordinary stop, and proved the project's named volumes still existed. Test-only cleanup then removed only the isolated project and volumes.

The first run identified that Qdrant's `/bin/sh` does not implement `/dev/tcp`; the healthcheck was corrected to invoke the image's verified `/usr/bin/bash` explicitly. The rerun above is the accepted evidence.
