# P2A-05 Evidence - Completed dependency

Status date: 2026-08-18

P2A-05 is verified. A `completed` dependency now releases its downstream service only after an upstream oneshot exits successfully. The existing `ready` dependency remains restricted to daemon services.

## Delivered behavior

- Manifest validation accepts `completed` only for an upstream `oneshot` service and accepts `ready` only for an upstream `daemon` service.
- DAG execution keeps downstream services in `waiting_dependency` until the required condition is satisfied.
- Oneshot exit code `0` releases `completed` dependents; nonzero exit leaves them waiting and fails the start Operation.
- Repeating `up` for the same valid manifest creates a successful Operation whose steps are all `skipped`; it preserves the active SystemInstance and does not rerun completed oneshots.
- Repeating `up` after the manifest changes returns `MANIFEST_CHANGED`; another non-running active instance returns `OPERATION_INVALID_STATE`.
- Explicit system restart creates a new SystemInstance and reruns its oneshot services.
- Systems with no declared ports produce a valid empty port plan and do not write lease or sticky-port history.

## Automated verification

Manifest tests cover valid and invalid `ready`/`completed` combinations. Port-planner tests cover an empty declaration without lease-store access. Orchestrator and API integration tests cover DAG release, upstream failure, repeated start, changed manifests, active-instance conflicts, and explicit restart.
