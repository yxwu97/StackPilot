# P2C-03 Evidence - Keycloak Configure

Status date: 2026-08-18

P2C-03 is verified and D-06 is closed.

## Implementation

- AIWS now provides `agent-runtime/configure_keycloak.py` backed by a testable `aiws_runtime.keycloak_configure` module. It is executed by the existing workspace Python venv Runner as a process `oneshot`; no BAT, PowerShell launcher, shell command, or HTTP command input is used.
- The program obtains a short-lived admin token in memory, reconciles the user-profile policy, locates the client and designer user by stable names, applies the planned Web origin/callback/logout values, and verifies the complete desired attribute set.
- Failures return a nonzero exit code and a bounded safe JSON message. The token and administrator password are never printed. Only exit 0 produces `Completed` and releases Server/Runtime through `dependsOn: completed`.
- Unit tests use an in-memory HTTP transport to prove identical repeated state and recovery when the client update fails after the profile update.

## Real D-06 Gate

`scripts/verify-p2c-03.ps1` created an isolated Keycloak project with a test-only credential and named data volume. It:

1. Started Keycloak 26.2.5 and wrote only the first profile stage to create a real partial state.
2. Ran the Configure program to completion, then ran it again unchanged.
3. Stopped the container without deleting the volume.
4. Recreated the same project and volume with Keycloak 26.3.3.
5. Ran Configure again and verified the running image version.
6. Removed the isolated container, network, and test volume.
