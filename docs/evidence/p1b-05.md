# P1B-05 Log Capture Evidence

- Migration `000003_runtime_logs.sql` adds the Phase 1B runtime identity foundation and closed `log_segments` index. Its SHA-256 is `6F95CBBCD7FDB9D25BF6258E2FEF7004D4D1BC89B3DC136E791A89831FA9D253`; after application it is immutable.
- Runtime identifiers now include documented `si_<ULID>` and `svi_<ULID>` forms. Raw spool content and redacted log messages are not stored in SQLite.
- The Log Manager tails stdout/stderr regular files only after canonical final-path validation under the configured data directory. Two owned readers feed one bounded writer, which assigns a strictly increasing ServiceInstance sequence in arrival order.
- CRLF, LF, empty lines, no-newline final content, and oversized lines are covered. Lines over 256 KiB are emitted in bounded chunks with `truncated=true`; readers do not use an unbounded Scanner token.
- Built-in redaction covers Authorization/Bearer, Cookie, credential query parameters, and connection-string credentials, followed by precompiled configured rules. Redaction failure is fail-closed: the event is neither persisted nor published, and the structured warning contains no original message.
- Final logs are per-stream NDJSON `.active` segments. Size/day rotation flushes and closes the file, atomically renames it, then registers only relative `logs/...` metadata with sequence/time bounds and size in SQLite.
- Final segment directories and history reads repeat canonical path, root-boundary, and regular-file checks. The repository rejects absolute/traversal/alternate-stream paths and enforces the ServiceInstance foreign key.
- Historical reads merge stdout/stderr segments by global sequence with bounded memory, support sequence/time/level filters and limit, deduplicate sequence values, and return `LOG_CURSOR_EXPIRED` semantics when a cursor predates retained bounds.
- The live event channel is bounded to 256 entries and uses non-blocking publication. A test that never consumed live events still persisted all 1000 input lines.
