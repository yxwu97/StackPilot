# P1B-03 Windows Supervisor Evidence

- `stackpilot internal-supervisor` is a hidden Windows-only command and is not listed in public CLI usage.
- Each instance Supervisor owns an exclusive Windows file-handle lock, one random Named Pipe, and one kill-on-close Job Object per managed service.
- The Pipe DACL is allow-only and contains exactly the runtime account SID and Local System. Every fresh connection verifies its OS-reported peer PID; a client must complete `hello` with a matching PID before any lifecycle request.
- The protocol accepts exactly `hello`, `start-service`, `inspect-service`, `stop-service`, and `shutdown-if-empty`. Frames are length-prefixed strict JSON capped at 1 MiB; arguments and environment are bounded and case-insensitive duplicate environment keys are rejected.
- A service is created hidden and suspended, assigned to its Job, given restricted instance-local stdout/stderr spool handles, and recorded in an atomically published `identity.json` before its primary thread resumes.
- Process identity uses PID, UTC creation time, canonical executable path, account SID, command digest, and protocol version. A mismatched identity refuses termination.
- A detached Supervisor remains reconnectable after its launcher exits. Two independent reconnects passed before service creation. Forced Supervisor termination closed the last Job handles and terminated both the service root and its descendant.
- `shutdown-if-empty` rejects an active service and closes the listener only after the successful empty response has been written.

Verified on Windows with the repository Go 1.26.6 toolchain:

- `go test ./internal/platform/windows/supervisor ./cmd/stackpilot -count=1 -v`
- `go vet ./internal/platform/windows/supervisor ./cmd/stackpilot`
- `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build ./...`
- `CGO_ENABLED=0 GOOS=darwin GOARCH=amd64 go build ./...`
- `git diff --check`
- SHA-256 equality check for `AGENTS.md` and `CLAUDE.md`

The Named Pipe lifecycle suite was run outside the restricted development sandbox because the sandbox denies local Pipe connections. It covered the live DACL, identity publication, complete protocol lifecycle, duplicate-Supervisor rejection, launcher exit, repeated reconnect, stdout/stderr, junction/alternate-stream spool rejection, identity mismatch, and complete Job tree termination.

Graceful process-specific termination remains owned by P1B-04; P1B-03 provides the bounded wait and full-tree forced termination primitive without claiming that later Driver behavior.
