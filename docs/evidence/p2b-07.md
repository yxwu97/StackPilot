# P2B-07 Evidence - Docker Compose security Gate

Status date: 2026-08-18

P2B-07 is verified. Compose execution remains a closed declarative surface and ordinary stop preserves named volumes.

## Enforced boundary

- The generated override contains only loopback TCP port mappings, non-Secret environment values, and four StackPilot identity labels; it cannot add commands, entrypoints, builds, mounts, privilege, or Secrets.
- Preflight rejects a managed service that enables `privileged`, overrides `entrypoint`, uses `build`, bind-mounts a host filesystem root, or depends on an undeclared service. ADR-0005 permits a fixed container `command` from the registered base Compose file; runtime overrides still cannot add or alter commands.
- Lifecycle commands use fixed argument arrays without a shell. Start always includes `--no-deps` and the declared service list.
- Ordinary stop is fixed to `docker compose ... stop --timeout ... <services>` and contains no `down`, `-v`, or `--volumes` path.
- Compose is enabled through an explicit Validator capability and `/version` advertises `phase2.compose`; the default Validator continues to return `FEATURE_NOT_ENABLED` for callers that do not enable it.

## Verification

Unit tests cover every denied config shape, acceptance of a fixed base container command, immutable override reparsing, path escape, exact Docker CLI arrays, identity tampering, and destructive-argument absence. The real Windows Gate also started a project with a named volume, recovered and rediscovered it, performed ordinary stop, proved the Compose-labeled volume still existed, then removed it only in isolated test cleanup.
