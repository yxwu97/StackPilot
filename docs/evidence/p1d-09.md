# P1D-09 Web Error Closure Evidence

- `web/src/api/stream.ts` provides one bounded fetch-based SSE client for domain events and logs. It resumes with durable cursors, handles chunked CRLF and multiline records, reloads REST snapshots after cursor expiry, backs off to 15 seconds, and stops on authentication or other terminal 4xx failures.
- Domain events only trigger authoritative REST snapshot refreshes. Manifest and runtime errors remain visible across background event refreshes, and all stream timers and requests are cancelled when their owners close or unmount.
- The log drawer reloads the recent durable window after interruption, resumes from the newest sequence, deduplicates entries, bounds visible history at 5,000 entries, and reports reconnect and paused-buffer overflow states.
- Invalid manifests disable start and restart while preserving stop for a running old snapshot. A digest mismatch displays the old-snapshot warning without changing runtime state in the browser.
- Node stream tests passed 6/6, including chunk boundaries, cursor expiry, reconnect bounds, log-window recovery, and terminal authentication failure. `npm run type-check`, `npm run build:web`, and `scripts/check.ps1` passed.
- Real Playwright verification against `http://127.0.0.1:32105` covered authenticated bootstrap cleanup, live BTC start/status/log/stop updates, simulated domain/log SSE 503 recovery without duplicate logs, invalid-manifest controls, old-snapshot warning, and persistent `MANIFEST_UNKNOWN_FIELD` after an external CLI Operation event.
- The final 390x844 log-drawer check confirmed stable sequence, timestamp, level, and message columns without overlap. Evidence is in `output/playwright/p1d9-log-mobile-final.png`; desktop and recovery screenshots are in the same directory.
- The fixture and BTC both ended in `stopped` with empty service and port lists. Server logs contained no runtime error, and the evidence/log scan found no Authorization, Bearer, cookie, CSRF, session, or bootstrap credential material.
