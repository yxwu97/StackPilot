# P1D-03 Periodic Reconciliation Evidence

Status: verified on Windows on 2026-08-18.

- Managed identities are checked every 10 seconds and stale lease reservations every 30 seconds. Server flags may increase, but not reduce, those intervals.
- The loop is owned by the server context, has bounded tickers, exits during shutdown, and never performs automatic restart.
- Workspaces with a queued/running/cancelling Operation are excluded from periodic runtime reconciliation. This prevents an in-progress dependency from being mistaken for restart residue.
- A real BTC run exposed and then verified this concurrency rule: the initial implementation marked the waiting Web dependency failed during Backend readiness; after the guard and regression test, the same 21-second start completed all 10 steps and stayed running through subsequent reconciliation windows.
- After the forced Server restart, one complete process interval preserved the same instance, Backend/Web PIDs, ready states, ports, and aggregate `running` state.

Verification: concurrency, minimum interval, identity outcome, aggregate state, lease TTL, and active-Operation tests pass in `internal/orchestrator` and `internal/storage`.
