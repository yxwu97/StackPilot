# P2B-04 Evidence - Docker Compose lifecycle

Status date: 2026-08-18

P2B-04 is verified. A standalone Windows Compose lifecycle adapter now owns deterministic project identity, fixed start and inspect commands, and non-destructive stop without yet enabling the manifest capability or orchestration path.

## Delivered behavior

- Project names are deterministic `sp-<system>-<workspace-short>-<instance-short>` values, bounded to 63 characters with a stable SHA-256 suffix when the system ID must be truncated.
- The persisted project identity includes the domain IDs, canonical workspace/data boundaries, base and override files, sorted managed service list, stop timeout, and a definition digest.
- Every operation revalidates the identity digest, both canonical file boundaries, the strict override shape, exact managed service set, and four StackPilot labels before invoking Docker.
- Start performs the P2B-02 preflight, then uses a fixed no-shell `up -d --wait --no-deps --wait-timeout <seconds> <declared-services...>` command. Undeclared Compose dependencies cannot be started implicitly.
- Inspect uses fixed `ps --all --format json --no-trunc` arguments and accepts both JSON array and NDJSON Compose v2 output. It rejects missing declared services, unknown services, incomplete container identities, and project mismatches.
- Stop uses only `stop --timeout <seconds> <declared-services...>`. The production adapter contains no `down`, `--volumes`, or `-v` path.
- Command streams remain bounded and are not exposed through error text. Timeout, start, inspect, stop, missing project, and identity mismatch have stable error classes and OpenAPI registry entries.

## Automated verification

Unit and contract tests cover short/long project names, deterministic truncation, fixed sorted command arrays, preflight ordering, running/stopped/degraded aggregation, JSON/NDJSON parsing, tampered identities, escaped overrides, exact labels, timeout cancellation, safe errors, and the absence of destructive stop arguments.

## Real Windows Gate

Command:

```powershell
$env:STACKPILOT_COMPOSE_LIFECYCLE_INTEGRATION='1'
go test ./internal/driver/compose -run '^TestInstalledComposeLifecycle$' -count=1 -v
```

Result:

```text

project=sp-btc-01arz3nd-01arz3nd container=sp-btc-01arz3nd-01arz3nd-database-1 health=healthy postStop=stopped
--- PASS: TestInstalledComposeLifecycle (7.43s)
```

The Gate cross-compiled the controlled static process fixture, built a local `FROM scratch` image without pulling a base image, generated the runtime override, and exercised real Docker Compose preflight, start/wait, structured inspect, ordinary stop, and stopped inspection. Cleanup then explicitly removed only the isolated Gate project and uniquely tagged image; a follow-up Docker query returned no matching containers or images.
