# P1B-04 Windows Process Driver Evidence

- `internal/driver` defines the use-side single-service Driver contract and immutable resolved process specification without importing HTTP, SQLite, or manifest DTOs into the domain layer.
- The Windows Process Driver accepts only `process/daemon`; `oneshot` returns `FEATURE_NOT_ENABLED` semantics and non-Windows implementations return the explicit Phase 3 platform gate.
- Preflight canonicalizes workspace, working, instance, and spool-parent paths, requires spools to remain inside the instance directory, bounds arguments/environment, rejects dangerous manifest overrides, and case-insensitively deduplicates the environment.
- The resolved executable is required to be a canonical regular file and is SHA-256 hashed again immediately before start. A digest change after Runner resolution is rejected.
- Start passes only structured executable, argument array, working directory, one-shot environment, command digest, and spool paths to the Supervisor. The Supervisor creates a hidden Windows console process group suspended, assigns its per-service Job, publishes identity, then resumes it.
- Runtime identity contains PID, UTC creation time, actual executable path, command digest, and an opaque platform token. The token identifies the already-running Supervisor and service; Stop/Inspect/Recover never launch a replacement Supervisor for an old identity.
- Stop first reconnects and compares the supplied domain identity with a live Inspect response. The Supervisor then independently re-verifies its held process identity immediately before signaling or termination.
- A detached Supervisor attaches to the service's hidden console, sends `CTRL_BREAK`, and waits until the entire Job reports zero active processes. A cooperative root and child exit with `Forced=false`; a native handler that ignores the event reaches the configured timeout and the full Job exits with `Forced=true`.
- Real tests verify no visible console window, inherited baseline and service environment, working directory, stdout/stderr, identity mismatch refusal, Start/Inspect/Recover/Stop, graceful tree exit, ignored-graceful forced tree exit, and no leftover fixture processes.

Verified on Windows with:

- `go test ./... -count=1`
- `go vet ./...`
- `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build ./...`
- `CGO_ENABLED=0 GOOS=darwin GOARCH=amd64 go build ./...`
- `git diff --check`
