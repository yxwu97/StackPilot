# P1C-02 Failure Policy Evidence

Status: verified on 2026-08-18.

- Failure policy parsing rejects unsupported values and resolves manifest defaults separately from request overrides.
- Default startup failure retains the failed service scene and prevents dependent services from starting.
- Cleanup-on-failure and cancellation stop only resources created by the current start execution, in reverse dependency order.
- Cleanup failures are aggregated and fail the Operation instead of being hidden; partial system-stop failures continue stopping other services and mark affected runtime state failed.
- Integration tests cover readiness failure retention, cleanup, cancellation convergence, cleanup failure, and partial stop failure.

Verified by `go test ./internal/orchestrator -count=1` and `go vet ./...`.
