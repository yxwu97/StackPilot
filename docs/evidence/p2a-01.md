# P2A-01 Windows Secret Provider Evidence

Status date: 2026-08-18

- D-12 is closed by ADR-0004. Windows uses current-user DPAPI files under canonical `DATA_DIR/secrets`, protected for the owning user and SYSTEM. Credential Manager was rejected because its generic credential blob limit cannot satisfy the accepted bounded 64 KiB Secret contract and its global lifecycle is not naturally isolated by `DATA_DIR`.
- The provider surface is limited to `Set`, `Resolve`, `Metadata`, and `Delete`. Keys use the manifest identifier grammar, filenames are SHA-256 key digests, encrypted strict-JSON records carry schema/key/version/UTC time/value, and resolved plaintext is returned in an owned buffer with explicit zeroing.
- Migration `000010_secret_metadata.sql` contains only system ID, name, provider, monotonic version, and update time. Repository tests passed for insert, idempotent replay, version advance, rollback rejection, read, delete, and forbidden-value-column inspection.
- Empty-database, repeated-open, historical migration, and direct v9-to-v10 upgrade tests passed. The migration count is 10 and checksum validation remains enforced.
- Real Windows DPAPI/DACL tests passed outside the restricted sandbox. They covered encrypted round-trip, ciphertext tamper rejection, deletion, and the existing local-auth DPAPI regression suite.
- A real combined SQLite/DPAPI integration test set and resolved `unique-p2a01-plaintext-never-persist`, closed SQLite, then scanned every database, WAL/SHM, and protected file below the isolated data root. No plaintext occurrence was found. The tamper error also did not echo the test value.
- `go test -race ./internal/security ./internal/storage -count=1` passed with repository-local MinGW 16.1.0. `scripts/check.ps1` passed Web tests 6/6, strict type checking, production build, all Go tests, and `go vet ./...`.
- `CGO_ENABLED=0 GOOS=linux|darwin GOARCH=amd64 go build ./...`, the production-function length check, and `git diff --check` passed. Non-Windows Secret storage remains gated until Phase 3.

P2A-01 is verified. CLI exposure, process injection, and runtime Secret-version snapshots remain owned by P2A-02 and P2A-03.
