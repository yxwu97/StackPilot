# P1B-06 Health Engine Evidence

- `internal/health` defines the Phase 1 `Checker`, `Result`, `ResolvedSpec`, readiness `Engine`, stable error codes, and the minimum Process Driver inspection dependency.
- Process readiness succeeds only while the persisted identity is still verified and running. Exit/not-found and identity mismatch terminate readiness immediately as `PROCESS_EXITED` and `PROCESS_IDENTITY_MISMATCH`.
- TCP readiness performs one context-bounded connection to a validated loopback host/port and distinguishes refusal from timeout without retrying inside a checker.
- HTTP readiness accepts only `http`/`https` loopback targets, disables proxy use, resolves every dial target and rejects any non-loopback answer, and never follows a redirect to another host or port. The body read is capped at 64 KiB and the optional redacted summary at 2 KiB; raw response bodies are never persisted.
- The readiness Engine checks once immediately, then uses injectable bounded jitter between sequential checks. It never overlaps checks, requires consecutive `successThreshold` results, honors the total deadline, and propagates Operation cancellation to the active check.
- Startup `failureThreshold` is accepted and validated but does not terminate readiness early, as required by the Phase 1 design. Phase 2 liveness behavior is not enabled.
- Migration `000004_health_results.sql` adds the constrained `health_results` table and newest-first service-instance index. Its SHA-256 is `2C0684107478D1645411E9F6DA1BA3DAE63BA82C34C920B1CB1D1789589D49DD`; after application it is immutable.
- The real SQLite repository enforces service-instance foreign keys, success/error consistency, valid UTF-8 summaries, a 2 KiB byte bound, bounded recent queries, UTC timestamps, and runtime cascade cleanup.
- OpenAPI, the Go API registry, and `docs/error-codes.md` register the eight runtime readiness codes with matching status, retryability, details policy, and safe messages.
