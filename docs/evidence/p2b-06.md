# P2B-06 Evidence - Docker Compose recovery

Status date: 2026-08-21 (failed-start stop recovery addendum)

P2B-06 is verified. Compose runtime identity is persisted independently from process identity, orchestration routes by driver kind, and a reconstructed control plane reattaches to the same real Docker project and log stream.

## Implemented adapter behavior

- Strict base64url/JSON project identity decoding rejects unknown fields, oversized tokens, altered definitions, and project-name mismatch.
- A new Lifecycle instance can revalidate canonical files/labels and inspect the same running project from the persisted token.
- Crash-window discovery uses fixed `docker ps` filters for system/workspace/instance labels, accepts at most 64 full lowercase container IDs, and parses one bounded `docker inspect` result only in memory.
- Every discovered container must match all StackPilot labels plus the Compose project/service labels and the declared managed service set.
- Recovered log follow supports a UTC RFC3339Nano `--since` cursor while the existing Log Manager retains durable spool offsets and sequences.
- Stable failures include `COMPOSE_DISCOVERY_FAILED`, project missing, and project identity mismatch.

## Persisted orchestration and control-plane restart Gate

- Migration `000014_service_instance_driver.sql` upgrades historical rows to `driver=process` and adds a bounded Compose-only `compose_project_token`; no PID is fabricated for containers.
- Start, stop, compensation, cancellation, service restart, aggregate state, readiness, port leases, and reconciliation route on the persisted driver.
- A missing token in the container-created/database-commit crash window uses bounded label discovery before the token is attached atomically with `waiting_ready`.
- A user Stop/Restart of a failed Compose runtime first performs the trusted preflight, so a stopped Docker Desktop daemon is started within the bounded deadline. If the token is missing, strict label discovery attaches the recovered identity atomically with `stopping` before non-destructive stop; an absent project settles to `stopped` without inventing identity.
- Recovery starts fixed Compose log follow with the newest durable log timestamp plus one nanosecond, then resumes Log Manager spool offsets and sequence state.

The controlled regression suite covers a failed runtime with no token and a discoverable labeled project, plus the negative branch where no labeled project exists. Both Stop Operations succeed without `down`, volume deletion, or process-driver fallback.
