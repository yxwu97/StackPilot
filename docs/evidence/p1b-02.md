# P1B-02 Runner Resolution Evidence

- `internal/runner` provides a Windows Phase 1 resolver for Maven, npm, and Java plus an explicit `FEATURE_NOT_ENABLED` boundary for `python-venv`.
- Resolution order is trusted server configuration, Maven Wrapper in the service/workspace, Java under `JAVA_HOME`, and then the service-account PATH. npm never resolves from `node_modules/.bin`.
- Workspace Wrapper and explicit executable paths use the shared Windows final-path trust boundary, including junction resolution. Explicit tools outside the workspace require a server-configured allowed root.
- Every selected executable is a regular file, receives a SHA-256 content digest, and passes a fixed, timeout-bounded version command. Only the parsed version is retained; probe output is capped at 32 KiB.
- `.cmd` execution uses an exported Windows-only builder with fixed `%COMSPEC% /d /s /c`, hidden/no-window process flags, and tested two-pass escaping for Wrapper argument forwarding.
- Real Windows tests preserve arguments containing spaces, Chinese text, embedded quotes, trailing backslashes, `%PATH%`, and `&` without expansion or command splitting.
- Linux and macOS builds expose only the explicit `PLATFORM_NOT_SUPPORTED` gate until Phase 3.

Verified with:

- `go test ./internal/runner ./internal/security ./internal/manifest ./internal/api -count=1`
- `go vet ./internal/runner ./internal/security ./internal/manifest ./internal/api`
- `STACKPILOT_RUNNER_INTEGRATION=1 go test ./internal/runner -count=1 -run TestInstalledRunnerToolchain -v`
- `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build ./...`
- `CGO_ENABLED=0 GOOS=darwin GOARCH=amd64 go build ./...`

The installed integration run resolved Maven 3.9.14, npm 11.12.1, and Eclipse Adoptium Java 21.0.10 through the production resolver.
