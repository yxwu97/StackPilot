## 1. 任务

优化 StackPilot Web 控制台“服务运行状态”中的日志查看体验。在不改变服务运行状态、不丢失服务端持久日志、不削弱 SSE 重连和脱敏边界的前提下，补齐自动换行、正文摘取、当前视图清空、抽屉全屏、日志分级显示、暂停/继续、TXT 导出和错误定位能力。

本任务是对现有日志查看器的增量完善。开始编码前必须先核对当前实现和契约，不能把已有的暂停、下载、级别、虚拟列表和有界缓存重复实现成第二套逻辑。

## 3. 当前事实与问题

- 服务详情使用宽度为 `min(760px, 100vw)` 的 `ElDrawer`，尚无全屏切换。
- 日志区采用每行固定 `26px` 的手工虚拟列表，正文使用 `white-space: nowrap` 和省略显示，长日志会被截断。
- 每行由 sequence、时间、level 和 message 四个相邻文本节点组成。拖动选择正文时容易连带选中序号、时间和级别。
- Store 已将可见日志限制为最多 5000 条；暂停时仍接收 SSE 并使用最多 5000 条的独立缓冲，溢出后恢复最近窗口。
- 页面已有暂停/继续和下载图标按钮，但状态反馈、导出命名/范围和验收要求需要完善。
- API 的标准日志级别为 `trace`、`debug`、`info`、`warn`、`error`、`fatal`，前端当前只对 level 标签做有限着色。
- 服务端日志是脱敏后的持久化事实，支持历史窗口、sequence cursor、SSE 重连和按单文件大小/跨日的 segment 轮转。
- 日志正文保存在 `DATA_DIR/logs` 下的 NDJSON segment 中；SQLite 的 `log_segments` 只保存路径、sequence/time 范围、大小等元数据，不保存 message 正文。
- `docs/detailed-design.md` 已定义 `logs.totalMaxBytes`、`logs.retentionDays` 和存储压力语义，但当前 `logs.Config`、Server 装配和 `LogSegmentRepository` 尚无对应保留配置、worker 或删除能力。该缺口不属于本前端工作包。
- 当前关键词筛选只作用于已加载窗口，不得包装成 Phase 3 的全文日志检索。

## 4. 核心原则

### 4.1 展示与持久化分离

- “清空”必须命名为“清空当前视图”，只影响当前浏览器内当前服务的日志窗口，不删除 NDJSON segment、SQLite 索引、事故证据或其他客户端正在查看的内容。
- 服务端磁盘增长不能靠“清空当前视图”解决。自动轮转与保留机制按 `prompt/prompt-20260819-03-service-log-retention-worker.md` 独立实现和验收；本前端工作包不以该 worker 完成为前置阻塞，但不能声称已经解决长周期磁盘增长。
- 不新增手工删除服务端历史日志的 API。若未来确需提供，必须作为独立高风险能力先更新设计、权限、审计、路径校验和恢复语义。

### 4.2 有界且可恢复

- 正常接收、暂停缓存、筛选、错误索引、复制上下文和导出都必须有明确容量或数据范围，不能因长时间运行形成无界数组、DOM 或 Blob。
- 暂停只冻结 UI 追加，不停止服务端日志采集，也不主动断开 SSE。
- SSE cursor、断线恢复、去重、过期窗口重载和脱敏行为必须保持不变。

### 4.3 可选择且可访问

- sequence、时间和 level 是辅助元数据；message 是主要可选、可复制内容。
- 日志级别不能只依赖颜色表达，必须同时保留可读 level 文本或等价标识。
- 图标按钮使用 Element Plus 现有图标并提供 tooltip、`aria-label`、键盘焦点和禁用状态，不手绘重复图标。

## 5. 功能需求

### 5.1 自动换行切换

- 正式实现前先完成一个有界 Spike，比较当前锁定 Element Plus 版本的 `ElTableV2` 动态行高能力（`estimated-row-height`）与自维护测量型虚拟列表。Spike 至少验证 5000 行混合高度、按 sequence 精确滚动、换行切换锚点、全屏尺寸变化、正文选择和移动端布局，并把选型结论及限制记录到实现计划或验证证据中。
- 若 `ElTableV2` 满足上述 Gate，应优先复用现有组件库；只有它不能满足日志正文选择、定位或布局契约时，才实现带高度测量/缓存的专用虚拟列表或评估新依赖。不得未经 Spike 直接手写复杂的动态高度前缀和算法。
- 在日志工具栏增加“自动换行/不换行”图标切换按钮，tooltip 和 `aria-label` 必须准确反映点击后的动作或当前状态。
- 默认采用“不换行”，保持高密度查看；用户切换后，在当前服务抽屉会话内保持选择。是否跨页面刷新持久化应沿用项目已有偏好设置方式，没有既有方式时不新增持久化。
- 不换行时允许日志区横向滚动或对单行提供完整内容查看，不能继续只用省略号造成内容不可达。
- 自动换行时 message 按容器宽度折行，长英文、URL、堆栈和无空格长串也不能撑破抽屉。
- 现有虚拟列表假定每行固定为 `26px`。开启换行后必须改为支持动态行高的虚拟化方案，或采用经压力测试证明有界且稳定的等价实现；不得只修改 `white-space`，否则 spacer 计算会导致日志重叠、跳行或定位错误。
- 切换换行前后尽量保持当前锚点日志可见，不应无条件跳回顶部。

### 5.2 正文摘取与复制

- 日志 message 使用独立可选择区域；sequence、时间和 level 默认 `user-select: none`，从正文中拖动选择时不能连带选中元数据。
- 保留浏览器原生文本选择和 `Ctrl+C`，不拦截或改写系统复制快捷键。
- 为单条日志提供“复制正文”操作，复制内容只能是该条已脱敏的 `message`，不包含 sequence、时间、level、stream 或隐藏 DOM 文本。
- 复制成功和失败应有轻量、可访问的反馈；Clipboard API 不可用时采用安全降级，不把日志写入控制台。
- 原生拖动选择只保证当前已渲染的连续行；在滚动触发虚拟行回收后，浏览器选区可能失效，不承诺跨屏原生拖选。不得为制造跨屏选择假象而暂时渲染全部日志或关闭有界虚拟化。
- 当前已渲染范围内的多行手工选择只包含所选 message 文本。可靠的跨行摘取通过基于 `LogEntry` 的“错误摘取”和当前查询导出完成，不从浏览器 selection 或 DOM 反向拼装。

### 5.3 清空当前视图与增长控制

- 在工具栏增加“清空当前视图”按钮。点击后清空当前服务已显示的日志窗口，并以最新已接收 sequence 建立新的视图边界；之后到达的新日志继续正常显示。
- Store 必须为当前服务抽屉会话分别维护 `viewFloorSequence` 与传输恢复所需的 `lastReceivedSequence`。清空时将 floor 设为当时最高已接收 sequence；清空可见数组后仍不得把 SSE 恢复 cursor 重置为 `0` 或退回较旧 sequence。
- 清空操作不调用 mutation API，不删除持久日志，不改变筛选条件，不改变服务状态，也不重置 SSE cursor。
- 暂停期间执行清空时，同时丢弃清空时刻之前的已显示日志和暂停缓冲，以该时刻最新接收 sequence 为边界；清空后到达的日志继续进入有界暂停缓冲。
- 所有进入可见列表或暂停缓冲的路径，包括初次加载、普通增量合并、SSE 重连、cursor 过期的 `replace` 恢复和暂停缓冲溢出后的窗口重载，都必须过滤 `sequence > viewFloorSequence`。恢复回调先从未过滤的服务端窗口更新传输 cursor/`lastReceivedSequence`，再按 floor 生成显示窗口，不能用过滤后可能为空的列表末项作为恢复 cursor。
- 清空后若发生 SSE 重连或 cursor 过期恢复，不能把边界之前的旧日志重新塞回当前视图。关闭抽屉、切换服务或重新打开服务时重置 floor，并可重新加载该服务的最近持久窗口。
- 空视图需显示明确空状态，且区分“尚无日志”和“当前视图已清空”时不得造成误解。
- 客户端可见窗口和暂停缓冲继续各自受 5000 条上限保护；错误索引和筛选结果必须从同一有界窗口派生，不复制一份无界日志正文。
- 本工作包只回归验证既有单 segment 轮转和历史/SSE 行为未被破坏。`retentionDays`、`totalMaxBytes`、元数据同步删除和存储压力由独立日志保留工作包负责。

### 5.4 抽屉全屏

- 在服务详情抽屉标题区域增加“全屏/退出全屏”图标按钮。
- 普通模式沿用当前有界宽度；全屏模式覆盖可用视口，日志区使用剩余高度并随视口变化，不产生文档级横向滚动。
- 全屏切换不能关闭抽屉、重载日志、重建 SSE 或丢失搜索词、暂停状态、换行状态、滚动锚点和错误定位位置。
- `Esc` 行为必须可预测：优先退出全屏，再次操作才关闭抽屉，或者采用 Element Plus 可可靠实现并有 E2E 覆盖的等价行为。
- 关闭后焦点返回打开服务详情的触发控件；桌面和 `390x844` 窄屏均不得出现工具栏重叠或文字溢出。

### 5.5 日志级别与颜色

- 按标准 level 统一显示：`trace/debug` 为低强调，`info/unknown` 为普通，`warn` 为警告，`error/fatal` 为错误。
- 颜色至少作用于 level 标识，并可对整行增加克制的背景或左边框提示；不能使用高饱和整行底色影响长时间阅读。
- `warn`、`error`、`fatal` 必须有不同于普通日志的非颜色标识。`fatal` 可以比 `error` 更强，但不能新增后端不存在的级别。
- `stderr` 只表示流来源，不能一律当作错误；错误判断以规范化 level 为准。
- 保证暗色日志背景下文字、焦点、选中态和级别标识有足够对比度。

### 5.6 暂停与继续接收

- 保留并完善现有暂停/继续按钮。暂停后按钮、状态标签和辅助文本必须明确显示“已暂停”，并显示当前缓存的新日志条数。
- 暂停时保持 SSE 连接和 cursor 推进，新日志进入有界缓冲但不改变当前可见列表和阅读位置。
- 点击继续后按 sequence 去重并按升序合并缓冲；若缓存溢出，按现有契约重新加载最近窗口并给出持续可见的提示。
- 暂停、继续、清空、筛选、换行、全屏之间必须可组合，不能出现继续后重复日志、跳回错误服务或内存无限增长。
- 切换服务或关闭抽屉时停止旧 scope 的流并清理该 scope 的 UI 状态，不能让旧服务日志进入新服务窗口。

### 5.7 导出 TXT

- 将现有下载能力明确为“导出当前日志”，输出扩展名为 `.txt`。
- 默认导出点击时当前查询结果中的客户端已加载窗口，而不是只导出虚拟列表当前渲染的 DOM 行，也不是导出服务端全部历史。当前窗口由初次最近 500 行和后续 SSE 增量组成，总量受 5000 条上限约束；没有筛选时导出当前视图边界之后的全部已加载日志。
- 导出内容按 sequence 升序，每条使用稳定文本格式：完整 UTC 时间、level、stream 和 message；不得包含未脱敏数据或内部文件路径。
- 文件名使用安全字符组成，并包含 system/service、实例摘要和 UTC 时间，例如 `btc-backend-si_01-20260819T073000Z.txt`。不得直接把未经处理的用户输入写入文件名。
- 空结果时禁用导出并给出原因。导出失败要有可见提示。
- 大窗口导出仍受客户端 5000 条上限约束；生成 Blob 后及时释放对象 URL。不得为了导出一次性请求无界历史或在 DOM 中展开全部日志。
- 当用户处于“错误摘取”模式时，另提供“导出错误片段”或复用明确命名的操作，仅导出当前错误及其上下文，不能混淆为全部当前日志。

### 5.8 错误定位与错误摘取

- 在工具栏提供“上一个错误”和“下一个错误”按钮，并显示 `当前序号/错误总数`。错误集合从当前筛选结果中 level 为 `error` 或 `fatal` 的日志派生。
- 定位必须使用稳定 sequence 标识，不使用数组下标、DOM 序号或文件 offset 充当事实游标。
- 点击定位后滚动到目标日志并给予短暂、非闪烁的高亮；在自动换行和不换行、普通和全屏、虚拟列表回收行的情况下都必须准确。
- 到达首尾时可以循环导航，或禁用越界方向；选择一种一致行为并通过 tooltip/状态表达，不允许点击无反馈。
- 搜索条件、清空视图、继续接收和服务切换后，错误索引必须重新从当前窗口计算；若当前锚点已不存在，选择最邻近的有效错误或清除锚点。
- “摘取错误”只复制当前错误片段：目标错误日志，加上同一当前窗口内最多前 5 条和后 5 条上下文。输出按 sequence 排序且每条只包含 message；不得包含窗口内其他无关日志、隐藏元数据或跨服务内容。
- 若相邻 error/fatal 日志间距不超过 2 条，可视为同一错误块，合并后仍将错误块外上下文限制为前后各 5 条。必须对边界、连续错误和重复行写确定性测试。
- 当前没有 error/fatal 时，错误导航和错误摘取禁用，并显示“当前窗口无错误日志”，不能退化为对 message 关键字做不透明猜测。
- 后端已提供 Incident 证据时，本任务仍只做当前窗口定位，不自行创建 Incident、不调用模型分析、不声称替代事故中心。

## 6. 推荐交互布局

- 工具栏第一组：关键词筛选、流连接状态、暂停状态/缓存数量。
- 工具栏第二组：自动换行、上一个错误、错误计数、下一个错误、清空当前视图、导出、全屏。
- 窄屏允许工具栏分行，但图标按钮保持稳定点击尺寸，搜索框不得把操作按钮挤出视口。
- 日志行维持“序号、时间、级别、正文”的可扫描结构；辅助列固定或粘性展示时不能覆盖正文。
- 复制单条正文、摘取错误等行级操作应按 hover/focus 出现，不能永久占用大量宽度；触屏和键盘用户仍必须能访问。
- 不新增使用说明卡片或大段页面内说明文字，状态和操作通过标准控件、tooltip、空状态和错误提示表达。

## 7. 实现约束

- REST/SSE、错误映射和认证逻辑继续集中在 `web/src/api`；跨视图共享状态进入 Pinia，纯展示状态可留在组件或专用 composable。
- 若 `App.vue` 因本任务继续膨胀，应按现有目录边界提取职责明确的日志查看组件，但不得创建空壳转发层。
- TypeScript 保持严格，不使用无理由的 `any`、非空断言或关闭检查。
- 优先使用 Element Plus 及其图标，不引入第二套组件库。动态高度虚拟化必须先通过 5.1 的 Spike 定型；只有现有 `ElTableV2` 不能满足 Gate 时才考虑专用实现或新增依赖，并说明维护状态、许可证、体积和替代方案。
- 不从 DOM 反向拼装导出、复制或错误上下文；这些结果必须从强类型 `LogEntry` 数据派生。
- 不用错误字符串推断 level；沿用 OpenAPI 和 Log Manager 的规范化字段。
- 所有导出和复制内容都来自已脱敏 DTO；不得读取原始 spool、内部 segment 路径或完整子进程环境。
- 不改变服务端日志 sequence、cursor、SSE envelope 和历史查询契约。确需改变 API 时，必须同步 OpenAPI、DTO、错误码和契约测试。

## 8. 状态与边界场景

至少明确并覆盖以下组合：

1. 无日志、只有普通日志、只有警告、只有错误、连续 error/fatal。
2. 单行超过抽屉宽度、无空格超长串、多行堆栈、单条接近 256 KiB 且 `truncated=true`。
3. 自动换行前后定位同一 sequence，切换全屏后位置仍正确。
4. 暂停后持续收到日志、暂停缓冲溢出、暂停时清空、清空后继续。
5. 清空后 SSE 重连、cursor 过期 `replace` 和暂停溢出窗口恢复均按 `viewFloorSequence` 过滤；即使显示窗口为空，传输 cursor 也不回退，旧日志不会重新出现。
6. 搜索后错误导航、搜索无结果、实时日志令错误总数变化。
7. 快速切换服务、关闭抽屉、系统停止、实例变化和组件卸载。
8. Clipboard API 拒绝、下载失败、空结果导出和文件名含非法字符来源。

## 9. 测试要求

- 为日志窗口状态增加单元测试：有界合并、暂停/继续、`viewFloorSequence` 与 `lastReceivedSequence` 分离、初次/增量/replace/溢出恢复过滤、空显示窗口 cursor 不回退、错误索引、错误块上下文、筛选和实例切换。
- 为日志组件增加测试：换行切换、当前渲染范围内正文独立选择/复制、虚拟行回收后的明确降级、level 样式、按钮禁用、暂停缓存数量、导出范围和全屏状态保持。
- 使用真实浏览器 E2E 覆盖桌面 `1440x900` 和移动端 `390x844`：长行、堆栈、动态行高虚拟化、滚动定位、键盘焦点、全屏/退出、暂停/继续、清空、导出和错误摘取。
- 以至少 5000 条混合长度、混合级别日志进行压力验证，确认滚动可用、DOM 有界、无明显布局跳动、无行重叠且工具栏不溢出。
- SSE 测试继续覆盖断开、重连、cursor 过期、去重和慢消费者；暂停不能阻塞服务端写入链路。
- 运行与变更范围匹配的 `npm` 类型检查、Web 测试、构建、Go 日志/API 测试和项目检查脚本，并报告实际命令、结果和未执行项。

## 10. 文档同步

- 纯前端交互且不改变契约时，至少同步与服务日志页面直接相关的开发说明、测试证据或进度记录。
- 本包不得顺带实现日志保留 worker；对应设计、存储和错误契约同步要求见 `prompt/prompt-20260819-03-service-log-retention-worker.md`。
- 若本包确实改变 API、DTO 或错误码，同一变更必须同步：
  - `docs/detailed-design.md`
  - `docs/overall-design.md`
  - `docs/phased-development-plan.md`（仅在阶段工作包变化时）
  - `api/openapi.yaml`
  - `docs/error-codes.md`
  - `docs/storage-schema.md`、migration 和对应升级测试（若意外涉及存储，应先重新确认范围）
- 不把 UI 截图当作 sequence、保留、清理或导出正确性的唯一证据。

## 11. 明确不做

- 不实现任意全文日志检索、正则查询或跨实例全库搜索。
- 不提供手工删除服务端历史日志、活动日志或事故证据的按钮/API。
- 不把暂停实现为停止日志采集、停止服务或永久断开 SSE。
- 不把 `stderr` 全部标记为 error，也不靠 message 中出现 `error` 字样替代规范化 level。
- 不导出无限历史、不绕过现有 5000 条客户端边界、不导出未脱敏内容。
- 不在日志查看器中新增模型分析、自动修复或自动重启能力。

## 12. 完成定义

只有同时满足以下条件才能声明完成：

1. 长日志可在自动换行和不换行间切换，完整内容可达，虚拟列表无重叠、错位或异常跳动。
2. 用户可只选择/复制 message；当前渲染范围内的原生选择、单条正文复制和错误摘取不会混入序号、时间、级别或无关日志，且不虚假承诺跨屏原生拖选。
3. “清空当前视图”行为明确，`viewFloorSequence` 在所有恢复路径生效，客户端内存有界，服务端持久日志未被删除；服务端长期保留缺口由关联工作包跟踪，不能在本包中误报为已完成。
4. 服务详情抽屉可全屏和退出全屏，状态、连接、筛选和定位位置不丢失，桌面与窄屏布局均可用。
5. 日志级别具有一致颜色和非颜色标识，warning/error/fatal 可快速识别且满足可访问性要求。
6. 暂停时仍有界接收，继续后无重复且顺序正确，溢出恢复有明确提示。
7. 客户端当前已加载窗口（初始最近 500 行加 SSE 增量、最多 5000 条）可导出为安全命名的 UTF-8 `.txt`，不会误导为服务端全部历史，空范围和失败状态处理完整。
8. 上一个/下一个错误定位准确，当前错误片段按确定性上下文规则复制或导出。
9. 类型检查、组件/Store 测试、构建、真实浏览器主流程及适用的 Go 日志/API 测试通过，验证命令和剩余限制已记录。
10. 未引入敏感信息泄露、无界缓存、破坏 cursor 恢复或跨阶段能力；如触及契约和存储，相关文档与机器可读契约已同步。
